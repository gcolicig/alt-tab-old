# Private exports of SkyLight and CoreGraphics

Generated on macOS 26.6 (build 25G72) with `dyld_info` against the dyld shared cache. The frameworks are
no longer files on disk, so `nm` on the bundle path finds nothing.

```bash
dyld_info -exports /System/Library/PrivateFrameworks/SkyLight.framework/Versions/A/SkyLight
dyld_info -exports /System/Library/Frameworks/CoreGraphics.framework/Versions/A/CoreGraphics
```

## Read this before using anything below

A symbol here is exported and resolvable. That is all it means. On 2026-08-07 five different write
operations against the WindowServer were resolvable, returned success wherever they return anything,
and had no effect. **Reading works, writing generally does not.** Every entry is a lead, never a capability.

## Where the names live

SkyLight exports only the `SLS` originals. The `CGS` names this project binds live in **CoreGraphics**.
`src/api-wrappers/private-apis/SkyLight.framework.swift` binds `CGS` names that do not exist in SkyLight
at all — the file name is misleading.

## Measured behaviour

| Symbol | Result |
|---|---|
| `CGSMoveWorkspaceWindowList` | returns `kCGErrorNotImplemented` (1006). A stub. |
| `SLSMoveWindowsToManagedSpace` | implemented — reaches `SLSWindowServerClientMoveWindowsToManagedSpace`. Takes `(CGSConnectionID, CFArray, CGSSpaceID)`; a raw pointer crashes the process. Called correctly it still moves nothing. |
| `CGSAddWindowsToSpaces` / `CGSRemoveWindowsFromSpaces` | no effect; documented in-repo as 10.10–12.2 |
| `CGSSetActiveMenuBarDisplayIdentifier` | accepted, returns 0, active display does not follow |
| `CGSManagedDisplaySetCurrentSpace` | reported Space changes, the screen keeps showing the old one, with or without `CGSShowSpaces`/`CGSHideSpaces` around it |
| `IOHIDSetAccelerationWithKey` | **works** — the effective pointer value follows immediately |
